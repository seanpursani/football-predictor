### Key Patterns Identified (from deep story analysis)

**Pattern 1 — Review process works:** Code reviews in Stories 1.4 and 1.5 caught 11 real issues combined (7 in 1.5 alone). Of these, 10 were fixed during the review cycle. The review workflow is producing value.

**Pattern 2 — NativeWind v4 configuration fragility:** Three files must be exactly right simultaneously (`babel.config.js`, `metro.config.js`, `tailwind.config.js`) or NativeWind classes silently fail with no error. This was documented in Story 1.1 dev notes but will catch contributors unfamiliar with v4.

**Pattern 3 — Jest/pnpm symlink friction:** Two stories (1.2 and 1.4) encountered Jest/pnpm compatibility issues. Custom `transformIgnorePatterns` are now in place, but new packages added in future stories may re-trigger this if they use ESM.

**Pattern 4 — Story file statuses drift:** Stories 1.2 and 1.3 show `Status: review` in their file headers, while sprint-status.yaml marks them `done`. The sprint-status file is the canonical source of truth — but story file headers should be kept in sync.

**Pattern 5 — Infrastructure stories don't have deferred items yet visible to Epic 2:** Several deferred items (hardcoded colour strings in placeholder screens, `gcTime` not set, double import of `@sentry/react-native`) are fine right now but accumulate. Story 1.4's placeholder screens will be replaced wholesale in Epic 5.

### Breakthrough Moments

1. **Story 1.1:** pnpm workspace protocol `workspace:*` resolved cleanly across all 4 workspace members — this was the biggest risk in the monorepo setup and it worked first try.

3. **Story 1.4:** The Zustand store anti-pattern test (`no store contains server data properties`) was a smart addition — it enforces the architecture boundary in an automated way.

4. **The schema-first approach paid off** — all 13 tables defined in Epic 1 mean Epics 2–9 build on a stable foundation without schema migrations mid-feature.
5. **NativeWind v4 three-file configuration is the top onboarding risk** — document it prominently for any new contributor.
