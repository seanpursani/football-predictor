## Challenges & Growth Areas

1. **Story 4.3 had the highest review load (5 patches) — some fixable with implementation habits**
   - Null guard missing on `gwMoment`/`momentType` in non-skipped path
   - `@ts-nocheck` at the top of the production Edge Function file (shortcut to avoid TypeScript errors at Deno entry point)
   - RPC errors swallowed silently (`assign_leaderboard_ranks` failing = ranks never assigned, no alert)
   - Error catch block secondary writes could throw and swallow the original error
   - `isCorrect=true` + no matching `match_events` row → `realEventMinute=null` → `calculateStreaks` throws
   
   Root cause pattern: implementation under deadline pressure without a defensive programming checklist.

2. **Missing migration discovered in review — DB prerequisites not mapped in story planning**
   - `0005_leaderboard_upsert_and_rank_rpc.sql` (unique constraints on `leaderboard_entries` + `assign_leaderboard_ranks` RPC) was needed for the Story 4.3 upsert and rank assignment logic.
   - Without the unique constraint, conflict resolution fails and duplicate rows are inserted. Without the RPC, rank window functions can't run.
   - Neither was flagged in the story spec. Discovery during review is the wrong time.
   - **Root cause:** No "DB Prerequisites" section in Edge Function story templates.

3. **Streak miss-interleaving required two algorithm redesigns**
   - Initial: misses sorted at `kickoff + 0` → sorted before correct hits in same fixture ❌
   - Iteration 1: sentinel `kickoff + 95min` → broke with tightly-spaced kickoffs ❌
   - Final: two-key sort (primary: kickoff time, secondary: `realEventMinute | Infinity` for misses) ✅
   - Root cause: sort key design, edge cases (ties, null minutes, same-fixture ordering), and expected output order were not specified in the dev notes before coding began.

4. **`@ts-nocheck` in production code — code quality standard violation**
   - Applied to `functions/run-scoring/index.ts` to bypass TypeScript errors at the Deno `Deno.serve()` entry point.
   - In a file handling financial-grade scoring data, blanket type suppression is unacceptable.
   - Patched in review: replaced with targeted `@ts-ignore` on specific lines only.

5. **Epic 3 retro was skipped — environment lessons were not propagated**
   - `@lecolpo/types` path mapping was missing from `apps/supabase/tsconfig.json` in Story 4.1.
   - Constants import path was wrong (`'../constants.ts'` → `'./constants.ts'`).
   - `moduleNameMapper` additions for Jest were needed and not pre-configured.
   - Had Epic 3 been retro'd, these Deno/Edge Function development environment lessons would have been documented and applied before 4.1 started.

## Key Insights

1. **Pure module isolation is load-bearing for correctness.** The scoring engine and streak calculator are the most mathematically complex code in the product. Making them pure functions — fully testable with no infrastructure — was the right call. Every future backend story with complex logic should start with the same question: "Can this be a pure module?"

2. **DB prerequisites belong in story planning, not review.** Missing migrations are the Edge Function equivalent of missing mocks in mobile stories. Any story that writes to the DB must enumerate required unique constraints, RPCs, and migrations in a "DB Prerequisites" section before implementation begins.

3. **Skipping retros has a cost.** Epic 3's undocumented Deno environment lessons (tsconfig paths, import path conventions, moduleNameMapper config) caused friction in Story 4.1. The iteration cost of discovering these mid-story was avoidable.

4. **Algorithm design notes prevent multiple implementation attempts.** Before writing any sorting or ordering logic, a brief design note covering: sort key, edge cases (null values, ties, miss entries), and expected output order must be written. Implementation begins only after the design is documented.

5. **`@ts-nocheck` is never acceptable in production code.** A targeted `@ts-ignore` with an inline justification comment is the only acceptable form of TypeScript suppression in non-test files. This is now a team agreement.

## Significant Discoveries

### Discovery: `match_result` event type produces silent zero-scoring in the reveal screen

**What:** The scoring engine defers `match_result` as an `eventType` in `match_events` with the note: "if `match_result` predictions appear, they will score 0 via the Precision Pick branch — acceptable for MVP."

**Impact on Epic 6:** Epic 6's Score Reveal screen will display a per-prediction breakdown. A prediction associated with a `match_result` moment type would show `eventPoints: 0`, all bonuses 0, `isCorrect: false` — with no explanation visible to the user, indistinguishable from a legitimate miss.

**Recommended action:** As part of Action Item #1 (scoring schema review), verify whether `match_result` moment types exist in the catalog seed data (Story 3.2). If they are not seeded, document explicitly that this code path is unreachable in MVP. If they are seeded, escalate to Alice for a product decision before Story 6.2.

**Status:** Verification pending (Action Item #1).
