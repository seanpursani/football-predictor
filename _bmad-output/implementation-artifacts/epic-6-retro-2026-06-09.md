## Challenges & Growth Areas

1. **Functional gaps reached review rather than implementation**
   - `captain-hit` case missing `onRevealComplete` callback — functional omission in the core animation flow.
   - Event icon colour ternary always returning `textMuted` — every state showed the same muted icon.
   - Running score counter not visible during reveal (AC2) — core UX feature of the reveal experience, not a polish detail.
   - Root cause: test suite passes because Reanimated mock doesn't execute animation callbacks. A green test suite does not verify that `onRevealComplete` fires at the right point in the animation chain.

2. **Double-write pattern appeared twice in 6.1** — `bgOpacity` written twice in both the `hit` and `miss` cases. Same class of error in the same file, which suggests the animation state machine wasn't walked through state-by-state during implementation.

3. **`fixtureTotals` reset regression introduced in 6.2** — The `useEffect(() => setFixtureTotals(new Map()), [gameweekId])` was dropped during the `moments.tsx` integration work, breaking the building/locked phases. Caught in review but represents a cross-phase regression risk in a screen that now handles four distinct states.

4. **NFR4 (3-second reveal load target) not measured** — The Definition of Done for 6.2 includes device verification and NFR4 confirmation. Neither appeared in the delivery notes. The performance target may be met, but we have no measurement to confirm it.

5. **`parseSupabaseRow` utility committed to in Epic 5 retro, not created** — Story 6.2's `useResultsQuery` still does inline snake_case→camelCase mapping with `as` casts. The same pattern the Epic 5 retro identified as the most recurring quality gap across all 5 stories.

6. **CaptainPopup `momentType` and Save button `isPending` — unknown status** — Both were action items from Epic 5 retro (items #5 and #6). Neither appears in Epic 6 story records. Status unknown — either fixed without documentation, or silently deferred again.

## Key Insights

1. **A green test suite is not a substitute for device verification on animation-heavy screens.** Reanimated's Jest mock executes synchronously and skips animation callbacks. Tests verify state shape, haptic wiring, and component structure — they do not verify animation sequencing or callback ordering. Device verification must be a hard gate.

2. **Process action items need the same gate enforcement as critical prep items.** Critical prep items (3/3) land because they block epic kickoff. Process items (4 of 8 addressed) don't have that gate. Future retro action items must be categorised as Critical (blocks next epic start) or Process (tracked as sprint-status sub-tasks with ownership).

3. **Documented lessons must become code.** `parseSupabaseRow` has been documented as a needed utility since Epic 2's Supabase mock factory lesson, reinforced in Epic 5's retro with explicit "write the utility once" language. It still doesn't exist. The lesson is clear — the follow-through mechanism is broken.

4. **`moments.tsx` is now the most complex screen in the app.** Four phases, two tabs, RevealSequence, RevealCards (firstView=false), streak chain connectors, streak break dividers, `fixtureTotals` reset, `AccessibilityInfo` migration. Epic 7 will add leaderboard wiring on top of this. It warrants careful integration testing before Epic 7 stories modify it.

**What:** `RevealSequence.tsx` post-reveal summary is already stub-typed for mini-league position display, with a dev note that `leagueId` doesn't exist on `LeaderboardEntry` yet (`packages/types/src/schema/leaderboards.ts`).

### Discovery 2: NFR4 performance target unverified

**What:** Story 6.2's Definition of Done requires the reveal screen to be ready to begin animation in under 3 seconds from app open on a mid-range device. No measurement appears in the delivery notes.

**Impact on Epic 7:** If the 3-second target is not met, it's cheaper to fix now (against the reveal screen) than after leaderboard infrastructure is layered on top.
