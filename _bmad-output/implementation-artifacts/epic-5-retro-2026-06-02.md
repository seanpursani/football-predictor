## Successes & Strengths

2. **Pure utility pattern established** — `deriveGameweekPhase` (5.1) set the precedent: pure function, injectable `now` parameter, deterministic tests. This pattern propagated to `buildPrecisionPick` (5.4) and `deriveBoldnessTier` (5.5), building a vocabulary of testable pure utilities.

4. **Test coverage growth was meaningful** — 161 tests at epic close, with component test files in `components/build/` and `components/moments/` testing behaviour rather than just rendering. Comprehensive coverage across queries, utilities, and UI components.

5. **Review process caught production-class bugs** — The missing `team_id` filter in 5.4 (would have returned ALL players in the DB) and the React Hooks Rules violation in 5.5 (all hooks after an early return — crash on phase null transition) were caught before shipping. The review process worked.

6. **Zero hard blockers** — Five stories, zero external stalls. The data pipeline from Epics 3–4 was a stable foundation.

7. **N+1 hook problem solved correctly** — `FixtureGroupSection` child component pattern in 5.5 is idiomatic React; hooks per component instead of hooks in a loop.

## Challenges & Growth Areas

1. **High review finding volume in Story 5.2 (14 findings, 11 patches)**
   - Story 5.2 was the largest story in the epic: 13 tasks, 7 new components, 5 new test files.
   - Preventable patterns appeared: null guard on joined Supabase rows, teamId filter silently dropped in Supabase chaining, retry button not calling `refetch()`, optimistic update ID collision (`id: -1`).
   - Root cause: large story scope combined with patterns (Supabase chaining, date parsing) that were documented but not yet systematised as shared utilities.

2. **Supabase data handling gaps recurred across all 5 stories**
   - ISO string → Date parsing was patched in 5.1, documented as a risk in 5.2, and still required mapper functions in every subsequent story.
   - snake_case → camelCase mapping was re-derived story-by-story via explicit parser functions.
   - The lesson was documented but never converted to a shared utility.

3. **React Hooks Rules violation in Story 5.5 — CRITICAL**
   - All `useMemo`, `useState`, and `useCallback` hooks were placed after an early `if (phase === null) return`.
   - This is a crash-class bug that would manifest intermittently on real devices when phase transitions through null.
   - Caught in code review and patched — but this check should happen at implementation time, not review time.

4. **CaptainPopup `momentType: null` deferred twice without resolution**
   - Deferred in Story 5.3 ("wire MomentType in Story 5.5 when catalog data is available").
   - Deferred again in Story 5.5 ("deferred to Story 5.5 where full MomentType catalog wiring is needed").
   - Result: the popup context label shows "Pick #N" instead of the event name. Visible UX gap, no assigned story.
   - This mirrors the `_layout.tsx` pattern from Epic 2: deferred debt compounding in a shared component across multiple stories.

5. **Epic 2 team agreement missed — Save button `isPending` state**
   - Epic 2 committed: "All toggle/submit buttons must be disabled during `isPending`."
   - Story 5.3 deferred "No loading/disabled state on Save button" without flagging it as a team agreement violation.
   - Agreement was accepted in review without challenge.

6. **Spec/AC drift in visual components (3 stories)**
   - ZoneChip labels rendered bare numbers ("5") instead of "±5" as specified — 5.4.
   - Fixture title in catalog header had identical ternary branches — 5.2.
   - BoldnessHeroCard missing middle-dot separator in subtitle — 5.5.
   - Tests passed because assertions weren't checking exact formatted strings for UX-specified components.

7. **Deferred items accumulating without a home**
   - 12 deferred items from Epic 5 alone, plus pre-existing defers from Epics 3–4.
   - No mechanism to surface which defers create a story obligation vs. which are acceptable to ship as-is.

## Key Insights

1. **Documented lessons must become code, not warnings.** Supabase ISO string parsing appeared as a risk note in dev notes for every story. A shared `parseSupabaseRow<T>()` utility would have prevented the recurring patches. Same lesson as Epic 2's Supabase mock factory: write the utility once.

2. **React Hooks rules check must happen at implementation time.** A pre-implementation checklist item — "are all hooks before any early returns?" — is cheaper than a code review patch.

3. **Deferred items require a story or a ship-as-is rationale.** Any `[Review][Defer]` touching user-visible features must either have a story assigned in sprint-status or carry an explicit "acceptable to ship to production as-is" rationale. Open-ended deferrals compound.

4. **Epic 6 prep is non-trivial.** `game_week_moment_players` table existence is uncertain, `expo-haptics` needs verification, Reanimated test mocking is not configured. None of these are blocking today, but all three gate Epic 6 story implementation.

5. **High review finding volume signals implementation patterns that need systematising, not just patch-and-move-on.** When the same class of error (Supabase chaining, null guards) appears across multiple stories, the fix is a shared utility and a checklist item — not another warning in a dev notes section.

## Significant Discoveries

### Discovery 1: `game_week_moment_players` table may not exist in production

**What:** Story 5.4 implemented `useMicroFlowPlayersQuery` with a primary join on `game_week_moment_players` and a two-level fallback (players table → error state). The dev notes explicitly flag: "the `game_week_moment_players` table may not exist in the production schema yet."

**Impact on Epic 6:** Epic 6's reveal cards show player names for Precision Picks. If this table does not exist, reveal cards show no player name for Precision Pick reveals — a significant UX degradation of the emotional centrepiece feature.

**Recommended action:** Verify table existence in production schema before Epic 6 kickoff. If absent, create migration. This is Action Item #1.

### Discovery 2: `react-native-reanimated` test infrastructure not configured

**What:** Reanimated is used in `DeadlineStrip` and `SkeletonRow` (Epic 5). Epic 6's `RevealCard` will use complex Reanimated sequences (spring, timing, repeat). The Jest test environment does not have `@react-native/jest-preset` or `react-native-reanimated/mock` configured for Reanimated animations.

**Impact on Epic 6:** Story 6.1 requires `RevealCard` tests covering all animation states (pending, hit, miss, captain-hit, jackpot). Without Reanimated mock setup, these tests will fail at the environment level, not the logic level — making it impossible to run a clean test suite during development.

**Recommended action:** Dana to configure Reanimated test mock before 6.1 implementation starts. Action Item #3.
